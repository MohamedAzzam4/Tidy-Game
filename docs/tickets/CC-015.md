## Behavior this ticket owns

The complete node-environment verification suite (vitest environment stays `node`;
`vite.config.ts` untouched). The user-required pure cases, all as named tests:

- **Mixed tiers**: 3 green + 1 red accepted physically on one tier, no feedback.
- **Completion on interchangeable tiers**: clean grouping completes on any of the four
  tiers.
- **Two and three collections complete simultaneously** (winning arrangement §8.4)
  through the public model API.
- **Tier independence**: 4 green + unrelated item on another tier still counts; on
  the same tier does not.
- **Anti-spam transitions**: put-back after pickup → no transition; cancel-restore →
  no transition; break-then-regroup → transitions once.
- **Occupied or undersized surfaces**: overlap rejection; towel-vs-stool rejection;
  occupied slot rejection (existing) + occupied surface area rejection + surface
  drop onto a slot-reserved AABB rejection (new) + floor drop onto an occupied mat
  shoe slot rejection (floor-surface reservation, C-5 × C-22).
- **Invalid and cancelled drops**: restore exact previous location from slot, surface
  and floor; no loss/duplication; restore-conflict fallback is deterministic.
- **Re-dragging placed items** from every location kind.
- **Reset**: same seed ⇒ identical layout (deterministic, positions compared exactly).
- **New Mess**: different layouts across draws; state fully cleared.
- **Scatter safety**: bounds, furniture exclusion, pairwise spacing, reachability
  (cell-based) for ≥ 100 sampled seeds.
- **Completable by construction**: slots-only solver driven by the model's own
  predicates finds a valid final arrangement for the shipped level and sampled
  seeds; `budget-exceeded` reported (never a silent pass) on an artificially tiny
  budget.
- **Static-decor effective bounds**: drops overlapping a static prop's AABB reject.
- **Tidy-all gating**: collections complete + stray floor item ⇒ not complete; a mat
  rest does not count (walkable floor); home slots do.
- **HUD-vs-card consistency**: progress and card gate agree in every tested state.

Note (N-4/N-5 ownership): the **preview-isolation assertion** is owned by CC-009;
this suite references it but does not own it.
