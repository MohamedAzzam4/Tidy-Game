## Behavior this ticket owns

All placement rules live in the pure model (node-testable, no DOM). One unified
`drop(itemId, target)` entry point for slots and surfaces; surface locations stored in
room coordinates; physical validity = footprint fits inside surface bounds, height
clearance ok, no overlap with items already on that surface; floor drops additionally
exclude furniture footprints. An invalid drop or a cancel restores the previous
location exactly — an item is never lost or duplicated — and every placed object
stays draggable. Single held-item invariant preserved. `isComplete()` keeps its old
semantics in this ticket; CC-007 flips the win rule.

## Interfaces / data contracts

```ts
// DropRejection gains:
'no-surface' | 'out-of-bounds' | 'insufficient-clearance' | 'footprint-overlap' | 'blocked-by-furniture'

// ItemLocation gains:
{ kind: 'surface'; surfaceId: string; x: number; y: number; rotation: number }

drop(itemId: string, target: DropTarget): DropResult;            // single entry point
validateSurfaceDrop(itemId, surfaceId, x, y): { ok: true } | { ok: false; reason };  // pure fit-check for ghosts
// a floor drop commits as { type: 'surface', surfaceId: 'floor', x, y } (the
// registry's floor entry) and stores location kind 'floor' (C-21); rule 4's
// furniture exclusion applies on top of the floor surface checks
```

**`findSurfaceAt` is cut (C-11)** — the DOM `data-surface` walk is the authoritative
surface resolver; the model-side query had no consumer, its carry-height filter
excluded R1's targets, and its no-hit contract was undefined.

- Overlap rule: axis-aligned footprint rectangles on the same surface must not
  overlap (tolerance ε = 0.01); touching edges allowed. **Occupied slots on a
  surface count too (C-5)**: each occupied slot's anchor reserves an immovable AABB
  (the category ghost footprint) on its hosting surface, so surface drops and slot
  occupants share one occupancy mechanism — a surface drop onto a slot-occupied
  spot rejects `footprint-overlap`; the adjacent spot succeeds. Slots anchored on
  walkable floor (the entry-mat shoe slots, which have no hosting `SurfaceDef`
  after C-22) reserve the same AABB on the `floor` surface entry — a floor drop
  onto an occupied shoe slot rejects `footprint-overlap`; the adjacent spot
  succeeds (C-5 × C-22 interaction, closed in revision 1).
- Clearance rule: `footprint.height ≤ surface.clearance` — this is what will reject,
  e.g., a tall upright book under too low a board.
- **Orientation binding (C-9)**: books on bookshelf tiers (slots or tier surface)
  are upright; everywhere else flat; the orientation feeds ghost, footprint and
  clearance uniformly.
- Slot path keeps today's rules unchanged (category gate, slot occupancy).
- Restore: the exact previous location; if it is now conflicting (possible only via
  out-of-band state changes, never in normal single-pointer play), a deterministic
  fallback applies — old slot occupied → floor near the drop point; invalid surface
  coordinates → floor near the drop point (C-18; today's implicit fallback,
  contracted).
- Progress counts **non-floor valid placements** (slot or surface; floor rests keep
  `kind: 'floor'` and do not count — C-21).

## Acceptance criteria

- A book can be dropped on the kitchen counter (organizationally wrong, physically
  valid) and stays there.
- Model-input contract for surface aiming: the model consumes the compensated
  surface coordinates produced by the view's surface-plane mapping (plan §8.3);
  the browser-side acceptance — a drag onto the visual center of the counter top
  lands within ε_aim (0.05 room units) of the aimed surface point — is owned by
  CC-005/CC-006/CC-016.
- A towel cannot be dropped on the stool (undersized) — rejected `out-of-bounds`,
  prior state intact.
- Dropping onto an occupied area of a surface rejects `footprint-overlap` without
  mutating state; a surface drop onto a slot-occupied spot rejects
  `footprint-overlap`; the adjacent spot succeeds (C-5 named tests); a floor drop
  onto an occupied mat shoe slot rejects `footprint-overlap` (floor-surface
  reservation).
- A floor drop inside a furniture footprint rejects `blocked-by-furniture`.
- Cancelled or invalid drop never loses/duplicates an item; restore returns the exact
  previous location (floor, surface or slot); the conflict fallback is deterministic.
- Placed items (slot or surface) can be picked up again and re-dropped elsewhere.
- Progress counts non-floor placements only.
- Pure node-environment tests only.
