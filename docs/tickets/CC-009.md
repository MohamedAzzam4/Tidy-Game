## Behavior this ticket owns

Turns every collection example from the brief into a named, pure (node-env) test:

- mixed tier: 3 green + 1 red on one tier — all drops accepted, no completion, no
  feedback;
- "clean" violation (same tier): 4 green grouped on a tier + an unrelated extra item
  on **that same tier** — green does **not** count;
- tier independence (inverse case): 4 green grouped on a tier + an unrelated item on
  **another tier** — green **does** count;
- interchangeable tiers: the same clean grouping completes on **any** of the four
  tiers (test all four);
- simultaneous completions: two collections (tier 1 + tier 2) and three collections
  (the winning arrangement, plan §8.4) complete at the same time;
- anti-spam (Q2): pick up a book from a complete tier and put it straight back — no
  transition, `collectionCompleted` empty; cancel-restore of a member — same;
  break-then-regroup — reports the transition again, once;
- quiet break: remove one book / add one foreign item to the tier → status silently
  false, no event emitted;
- tidy-all gating: all collections complete + one book left on the floor ⇒ level NOT
  complete; a mat rest also does not satisfy tidy-all (walkable floor); placing the
  book on any valid non-floor placement ⇒ complete;
- preview isolation (owned here, per N-4): a static assertion that the ghost/preview
  query surface (`validateSurfaceDrop`, `findDropTarget` — `findSurfaceAt` is cut)
  does not expose collection state (type-level exclusion + runtime shape check).
  The runtime **zero-invocation assertion** over a full drag lifecycle lives in the
  e2e layer (CC-009 adds the pure-side check; CC-016 drives the browser side).
