## Behavior this ticket owns

Replayable, deterministic layouts:

- **Seeded scatter**: pure `src/game/scatter.ts` with mulberry32 PRNG; rejection
  sampling over reachable floor space — room bounds minus wall margin minus furniture
  footprint AABBs (rug/mat walkable) — with footprint-aware spacing (scattered AABBs
  non-overlapping + ≥ 0.2 gap; the “≥ 0.7” shorthand is center-to-center for the
  small-item class = mugs/books/shoes/towels; cushions covered by the AABB rule) and
  ≥ 0.5 clearance from furniture; per-item small rotation (±21°, today's range).
- **Fallback chain** (documented, reliable): (1) relax spacing stepwise, (2) fall back
  to a jittered grid over walkable space, (3) fall back to the shipped hand-placed
  default layout from CC-011. Always terminates in a valid layout.
- **Reset** re-scatters with the **same seed** → identical layout;
  **New Mess** draws a fresh seed → another layout and resets all state (collection
  status quietly cleared).
- **`?seed=` URL parameter** pins the layout for deterministic tests. Untrusted
  input (C-19): parsed to a finite integer, clamped to uint32, invalid or
  out-of-range → default seed.
- **Validation helpers exported for tests (signatures pinned, C-12)**:
  `hasValidArrangement(level, positions): { ok: boolean; reason?: 'no-arrangement' | 'budget-exceeded' }`
  and `isLayoutReachable(level, positions, cell = 0.15): boolean`. The solver
  generates and checks moves **only through the model's own predicates**
  (`validateSurfaceDrop`, slot rules, the tier-clean rule) — never a second,
  drifting ruleset. Search space: **slots-only** (32 slots ≥ 28 items; sufficient —
  the winning arrangement §8.4 uses only slots) with a declared step budget;
  exceedance reports `budget-exceeded`, never a silent pass. **Reachability,
  operationalized**: start cell (0.15 grid) outside every footprint (items +
  furniture); no free-space path search (drags fly over furniture). The solver
  consumes the static-decor-adjusted effective surface bounds (C-7).
- **HUD wiring**: buttons + "Play again" = New Mess.

## Acceptance criteria

- Reset twice in a row → pixel-identical scatter after settle.
- New Mess twice → at least one differing position (deterministic assertion).
- ≥ 100 sampled seeds pass scatter safety + reachability + arrangement solver in tests;
  an artificially tiny budget reports `budget-exceeded` (named test).
- The winning arrangement (§8.4) passes `hasValidArrangement` and completes the level
  through the public model API.
- Invalid `?seed=` values (non-numeric, float, out-of-range) fall back to the default
  seed.
- Buttons work with pointer and keyboard; completion card resets cleanly.
