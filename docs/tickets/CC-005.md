## Behavior this ticket owns

The drag-time experience for free placement. The view stays rule-dumb: it asks the
model where a drop may land and only renders the answer.

- **Surface targeting**: deterministic precedence chain (plan §8.3, C-10):
  (1) slot match (existing radius + carry-height compensation) wins; else
  (2) `elementsFromPoint` → nearest `[data-surface]` ancestor, floor projection as
  fallback; else (3) implicit floor — a floor drop commits as
  `{ type: 'surface', surfaceId: 'floor' }` and stores location kind `'floor'`
  (C-21). **Surface-plane aiming (C-2)**: when a surface
  is hovered, the pointer maps through that surface's plane — the floor-projected
  point is shifted by `(+topZ, +topZ)` (the exact inverse of the projector's z
  offset; generalizes the slot path's compensation) — and that surface point drives
  `validateSurfaceDrop`, the ghost, the committed `DropTarget.surface.{x, y}` and
  the settle anchor. Tagging surfaces directly in the SVG solves the isometric tier
  ambiguity without ray-casting.
- **Ghosts**: the item's current-orientation footprint outline at the live surface
  point, projected onto the hovered surface's plane (`topZ`), showing **physical
  fit only** — `fit` (soft teal outline, current style) vs `no-fit` (dimmed +
  diagonal strike). Exactly one ghost mid-drag: a slot match suppresses the surface
  ghost (the existing e2e assertion survives). Never collection correctness: the
  ghost code path must not read collection state at all.
- **Drop UX**: settle animation to arbitrary `(x, y, topZ)`; restore on invalid drop,
  Escape and pointercancel from slot, surface and floor alike; the existing
  floor-plane clamps stay — elevated surfaces are reachable through the
  surface-plane mapping (no clamp widening needed).
- **Debug hook (C-13)**: `__cozy.itemClientPos` gains a surface branch —
  `surface → (x, y, topZ)`; the hook stays read-only. Lands here, before
  CC-006/CC-016 re-drag-from-surface scenarios can aim surface starts.
- Existing slot aiming (carry-height compensation, `DROP_RADIUS 0.95`, zone labels)
  is untouched.

## Acceptance criteria

- Hovering the counter shows the counter ghost at surface height; hovering a
  bookshelf tier shows that tier's ghost.
- **A drag onto the visual center of the counter top lands the item within ε_aim
  (0.05 room units) of the
  aimed surface point** (surface-plane aiming acceptance, C-2); the e2e harness aims
  through the existing `clientFromWorld(x, y, topZ)` round-trip.
- A physically invalid target (towel over stool) shows the `no-fit` ghost and the
  item restores on release.
- Exactly one ghost is visible at every moment of a drag (slot ghost suppresses the
  surface ghost when a slot is targeted).
- Placement previews never encode collection membership/correctness (color, label,
  marking, glow).
- Escape / pointercancel restore items held from slot, surface and floor.
- All 20 existing tests pass; existing e2e steps 1–6 stay green.
